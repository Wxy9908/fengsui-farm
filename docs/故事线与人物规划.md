## 1. 定位：故事线在这款游戏里是什么

故事线**不是独立玩法模式**，而是包在经营循环外面的一层「意义与目标」：

- 给「做菜」一个顾客——菜品不再只是卖给抽象商店，而是端给具体的人；
- 给「赚钱」一个去处——金币和图鉴进度推进故事章节；
- 给「收集」一个情感钩子——每个 NPC 是一段小故事，图鉴之外多一套「人」的收集；
- **v2 增补**：给「交易」一张脸——小铺是林婶的杂货铺；卖菜不是点按钮，是跟人打交道；
- **v2.1**：给人一个「在哪儿」。见面挂在地点上。现在的田地/厨房/小铺/订单/图鉴页，只是这些地点的临时入口；地图做好后，玩家像走小镇一样串起这些人，不再靠底栏把人叫出来。

操作形态仍是可点击场景（热点进地点、进对话），不做自由摇杆漫游。学的是星露谷的**「人住在地方里」**，不是它的像素角色操控。

**一句话：经营循环不变，故事线负责回答「我为什么回来、在为谁种地、走到哪儿才能见到谁」。**

### 不做清单（防膨胀，与首版同样严格）

- 不做分支网状剧情、不做选项影响结局——全部线性小节 + 收集解锁；
- 不做 NPC 日程/走动/好感下降等拟真系统——好感只升不降（地图阶段也是「人在固定地点等你」，不先做全镇巡逻）；
- 不做恋爱结婚——温情向，不做攻略向；
- 不加新 NPC（v2 定案：6 人加深，不扩编）；
- M5 不实装果园/养殖/钓鱼玩法（只预留数据接口，见 §7.4）。

## 2. 世界观与基调

**背景**：玩家在城里打工多年，因 §2.1 的缘故回到儿时生活过的小镇「丰穗镇」，接手外婆留下的老农场和一间歇业多年的小食堂。小镇曾经以一年一度的「丰收祭」闻名，如今已停办多年，年轻人离开，铺子冷落。外婆在玩家回镇之前已经不在了——回镇不是奔丧，是去接她留下的地和食堂。

> 定名留痕（2026-08-11）：游戏正式定名「**丰穗小镇**」——镇名即游戏名，本文档的世界观从此直接是游戏标题；品牌标志为金色麦穗徽章（详见《美术风格规范》版本记录）。

**主线一句话**：用一年的时间重新种出好菜、做出好菜，把「丰收祭」办回来，让小镇重新热闹起来。这个节日的来历、过法和每人的含义写在 §6.4，正文里按章节一点点说出来，不在开场讲完。

**基调**（对齐已定「暖色田园」美术基调）：

- 暖、轻、慢——没有反派、没有死亡、没有失败惩罚，矛盾都是「小事」：一道做不出的菜、一个不好意思开口的请求；
- 幽默但克制——黑暗料理、失败试验可以是笑点素材，但不玩烂梗；
- 文案量级：单段对话 3~8 句，碎片化呈现，适配手机端与碎片时间，绝不铺大段文字墙；
- **v2 增补·温暖感的来源**：温暖不是靠"感人台词"堆的，是靠**细节的回响**——小满上次说想吃的东西，下次对话里他还记得；白婆婆讲过的往事，会在丰收祭上被另一个人提起。文案设计必须维护这种「镇上的事大家都记得」的感觉（§9 文案规范有检查项）。

### 2.1 序章：为什么回来（2026-09-28 用户定稿方向）

玩家进游戏时不应已经站在田里却没人解释。序章在主线第一章「重新开张」之前，只交代来历，不教学、不发任务。可跳过；跳过仍视为已读，老存档默认已看过。

两封信分开，不要混成一件事：

- **田伯的信**在城里就到了，是回镇的契机，并勾起回忆；
- **外婆的信**不在序章里出现。玩家回到农场上的老屋之后，自己找到——小彩蛋，不挡进度，找不到也不影响主线。

| 段 | 发生了什么 | 呈现 |
|----|------------|------|
| 办公楼 | 同一层楼、同一张桌、同一轮汇报。钟走，人不动。老板的话翻来覆去：还不够、再改、这点都做不好。午饭是同一家外卖。 | **小动画 1**：循环镜头（工位→时钟→老板的嘴→外卖盒），两三轮就够，不写长对白，不点公司名 |
| 信 | 田伯的信到了。不讲遗产，只讲镇上的地还在，他先看着。 | 一封信打开即可，钥匙/围裙可夹在信里，当作「回来用得上」 |
| 想起 | 信让玩家看见从前：小镇、小时候在田埂和食堂木桌边、外婆。 | **小动画 2**：从信纸叠化到旧日（田、孩子、外婆的背影或一碗热饭），暖、短，不写成悼词 |
| 决定 | 玩家自己离开这栋楼，坐上回丰穗镇的车。窗外从楼变成田。 | 动画收束，一句内心即可 |
| 到站 | 人从**进村路**走进来，路过村口杂货铺与旅馆；田伯在农场等。序章结束，进入可玩的第一天。第一章仍是发现食谱、重开食堂。 | 第一句人话来自田伯 |

动画纪律：两段都是序章里的短循环，可跳过；不做分支，不做玩家操作。老板只作为「把日子磨平的声音」，不进小镇、不当反派。

**彩蛋·外婆的信**（回镇之后，不在序章）：

- 地点：农场上的老屋（外婆的家）。地图期挂在 `home`；地图未做时，可先藏在田地页小屋可点的抽屉/相框，找到一次即永久已读。
- 内容方向：外婆生前写给玩家、没寄出或压在家里的话——欢迎回来、食堂和地留给你、饭要自己做着吃。不揭丰收祭谜底，不替田伯把序章再说一遍。
- 奖励：无数值或极少（一句收藏进图鉴/信件匣）。找不到不惩罚。

### 2.2 地图：人住在地方里（远期，本期不实装）

后期做地图。玩家与 NPC 的关系不是「切到某一页就弹出这个人」，而是像星露谷那样：**走到某个地方，才遇见常驻在那里的人**。底栏五页是地图完成前的代用品，逻辑上已经按地点记账，避免以后推倒重写。

| 地点 id（预定） | 现在用哪一页顶着 | 常驻的人 | 玩家来这里做什么 |
|----------------|------------------|----------|------------------|
| farm 农场 | 田地 | 田伯（田埂、种子） | 种、收 |
| home 老屋 | 尚无（彩蛋可先挂田地小屋） | 无常驻；外婆的信藏在这里 | 回镇后自己找到，不挡主线 |
| canteen 食堂 | 厨房 + 图鉴（外婆的手抄本在食堂） | 白婆婆（门口坐着） | 做菜、翻食谱 |
| shop 杂货铺 | 小铺 | 林婶 | 把货卖给她、升级、每日的事 |
| orders 今日的嘴 | 订单页（临时集中入口） | 当日点单的人 | 地图期改为：单子出现在那个人所在的地点，不再单独一页 |
| lane 镇路 / 学校路口 | 尚无 | 小满 | 放学后来讨吃的 |
| inn 旅馆 | 尚无 | 沈先生 | 高级单、找那碗汤 |
| roadside 后来才到的路口 | 尚无 | 阿远 | 丰收祭前才出现 |

约定（写给以后的地图，也约束现在的引导）：

1. 对话、引导、求购的触发条件写**地点**（`place: farm`），不写死「第几个 tab」。现在页面只是把地点打开。
2. 地图第一版 = 可点的小镇热点（农场、食堂、小铺、人家门口），点进去仍是现在这些经营界面。不做摇杆走路，不做 NPC 白天换点巡逻。
3. 订单页在地图期收掉：你去田伯那儿看见他今天想吃什么，去林婶那儿卖货。好感仍是交单涨，不新做一套。
4. 序章的「到站」落在进村路，人从村口走进来；田伯在农场等，第一句人话来自他，而不是系统说明。
5. 平面按 `docs/mockups/map.svg`：村口路北杂货铺、路南旅馆；路与食堂之间是丰收祭空地，不另开店；食堂居中，白婆婆的小屋贴在食堂旁，厨房在食堂里面；学校在食堂北侧，小满家在这条路上；我家与田地挨着，田伯靠后山。后山小路、田地外侧的空草地、南缘的河只留白，本期不做成玩法。

## 3. 系统结构：三件套 + 声望轴

故事线由三个互相咬合的系统加一条进度轴组成，全部数据表驱动（沿用《数据表设计》「配置只读 / 存档运行时」分离原则）。

### 3.1 NPC 系统（`data/npcs.json`）

每个 NPC 是一份配置：身份、性格、喜好菜品、最爱菜、好感等级阈值、解锁的对话与奖励。详见 §4 人物表。

### 3.2 NPC 交易系统（`data/orders.json` 或动态生成规则）——本块的地基，最先做

v2 将 v1 的「订单」升级为「NPC 交易」，三种形态：

| 形态 | 说明 | 定位 |
|------|------|------|
| **求购单** | NPC 要某道已发现食谱的菜（或作物），限时/不限时交付；报酬 = 售价 × 溢价（1.2~1.5）+ 好感 | 主力形态，菜品第二出口 |
| **赠送** | 玩家主动送 NPC 喜欢的菜（每日限次防刷），回报好感 + 偶发回礼线索 | 好感的日常来源，零压力社交 |
| **以物易物** | 少数剧情交易：NPC 用种子/线索/专属食谱换指定菜品（不涉金币） | 剧情节点专用，手配 |

- 设计意义（沿用 v1，依然成立）：
  - 菜品第二出口且溢价高于直卖——回应「直接卖 vs 做菜」定价取舍（该悬案 2026-08-11 已由数值裁决收口，交易系统是体验层的呼应）；
  - 交易目标 = 天然的每日/每阶段小目标，解决前期「等待成熟时无事可做」的节奏问题；
  - 求购单要求「已发现的食谱」→ 玩家为接更好的单主动试新组合——给支柱 2 装发动机。

**商店人格化（v2 新增）**：商店页 = 「林婶的杂货铺」。分两期走——
- 一期（**P0b 起**，纯文案/呈现层）：页面标题、卖出确认、今日特价黑板、缺货提示全部改为林婶口吻（「这个价给你，别跟外人说」）；
- 二期（求购上线后）：林婶成为真实的批量交易对象（批发单、订单刷新增益的来源人设）。

### 3.3 好感度与剧情系统（`data/stories.json`）

- **定案：好感数据层已在 P0b 落地**——`npcs.json` 阈值与存档 `affinity` 随求购记账（先记账后开花）；**P1** 做薄层对话解锁，**P2** 深写与 UI 完整呈现。
- 好感来源：完成交易（主）+ 赠送喜欢的菜（辅，每日限次）+ 送出「最爱菜」有额外加成（§4 每人标注）；
- 好感升级解锁三类奖励，按优先级：
  1. **剧情对话**：该 NPC 的支线小节（v2 加深为 8~10 段/人，见 §4）；
  2. **专属食谱**：NPC「教你一道菜」——食谱自动点亮进图鉴，食材仍需自己种。**食谱发现第二渠道**，专属食谱标记 `source:"npc"`，组合解析跳过，不与组合表重叠；
  3. **经营增益**：种子折扣、订单溢价提升、厨房队列+1 等——全部复用现有数值体系，不引入新机制。
- 剧情触发条件数据化：`{type:"affinity", npc, level}` / `{type:"recipesDiscovered", count}` / `{type:"reputation", level}` 等。

### 3.4 小镇声望轴（v2 新增，`reputation`）

用户定案：数值不能只有金币，需要更多维度的阶段性提升。设计：

- **定义**：声望 = 玩家在小镇的「人缘与口碑」，与农场等级并列的第三进度轴（金币=支付手段、农场等级=经营深度、**声望=人际关系广度**）；
- **来源**：完成 NPC 交易（按单计）、好感升级、主线章节推进、丰收祭相关行为——全部来自"与人打交道"，种地卖菜本身不涨声望（双轴分工清晰）；
- **用途（门控，不设消耗）**：高阶求购单解锁（T3/T4 菜品单要声望等级）、NPC 信任剧情（某些支线小节要声望门槛）、丰收祭筹备资格（第四章主线条件之一）；
- **阶段性提升**：声望等级用镇民称呼体现（外乡回来的 → 食堂的 → 自己人 → 丰穗镇的骄傲……），升级复用现有庆祝层播仪式感；
- **数值原则**：曲线与农场等级解耦但节奏对齐（正常游玩下两轴前后脚升级）；表结构入《数据表设计》，存档字段 `reputation`，`??=` 迁移。

### 三件套+声望轴与三大支柱的对齐审判

| 系统 | 支柱1 收获期待 | 支柱2 组合惊喜 | 支柱3 经营积累 |
|------|--------------|--------------|--------------|
| NPC 交易 | 订单催你种特定作物，收获有了"人等"的期待 | 接单需要先发现食谱 → 主动试组合 | 交易溢价 + 每日目标 |
| 好感/剧情 | NPC 喜欢的菜引导种植方向 | 专属食谱 = 新的发现时刻 | 好感奖励增益经营效率 |
| 声望轴 | 高阶单要求更稀罕的作物 | 声望解锁的高阶单牵引探索 T3/T4 组合 | 称呼进阶 = 长期积累的可见刻度 |
| 主线章节 | 章节目标要求集齐作物/菜品 | 章节食谱只能靠探索补全 | 丰收祭 = 长期积累的验收仪式 |

**结论：全部落在支柱上，无一项削弱核心循环。**

## 4. 首发人物表（6 人 · v2 深写版）

设计原则：数量克制（文案成本 = 人数 × 段数）；每人必须有**功能定位**与**情感弧线**；喜好绑定现有 15 作物 / 40 食谱，不等人设倒逼新内容。支线小节标题为 AI 起草大纲，写作时允许微调。

**视觉定妆（与文案分工）**：性格/口癖以本节为准；头像画法、裁切、出图流程以 `docs/美术风格规范.md` §4.4 与 `docs/即梦出图管线.md` 阶段 3 为准。定妆图目录 `docs/mockups/npc/`——现有 `sc1.png` 为**田伯方向样**（可用；入库前去水印、弱布纹）。林婶 / 白婆婆 / 外婆及其他人**尚缺定妆**，补齐前不放量 NPC 头像。**排期：等已有图标/背景重做完成后再做（先旧后新）。**

### 4.1 田伯（tianbo）

- **身份**：隔壁退休老农，看着玩家长大；外婆的老邻居——全镇公认的「爷爷型」人物。

### 6.4 丰收祭：来历、过法、对每个人的意义（2026-09-28）

写作用。节日是主线的终点，也是前面每段闲话要慢慢喂给玩家的东西。单段仍守 3~8 句，本节是作者心里的全貌，角色每次只说出自己那一角。

**为什么会有这个节日**

丰穗镇种得出粮食以后，有过一年收成薄、各家把粮关在自己屋里。镇中那块空地（村口与食堂之间，见地图）上，有人把自家剩的一口饭摆出来，说：薄年也坐在一起吃，丰年也坐在一起吃。后来每年收完最后一茬，就在这空地上摆长桌。麦穗是那年桌上第一样能分的粮食，镇名、游戏名、金色麦穗徽章都从这一晚来。

它庆的是「这一年的收成放到同一张桌上」，不是评比谁种得最好，也没有祭司、比赛、冠军。食堂在镇中间，因为这张桌的热菜从食堂端出来。外婆在的那些年，她是这口灶的人。

**为什么停了**

没有人宣布取消。年轻人去了城里，食堂歇了，凑不齐一桌人，也没有人把热菜端到空地中央。灯笼还挂在田边，一年年褪色。停办是人少了、灶冷了，不是一场灾，也不是谁的过错。

**当晚怎么过**（终章按这个顺序演，前面章节只预告其中一两步）

1. 白天，田伯把这一年地里的东西摆到空地上给人看。摆出来就行，不打分。
2. 林婶的杂货铺挂上「今日歇业，去帮忙」。桌、碗、灯笼由她备。
3. 午后，小满沿着镇路把褪色的灯笼点上。田地页远处那串灯笼，就是这些。
4. 黄昏，食堂出三道摆在长桌正中的菜，用的是现有食谱，不新做菜：
   - **烤面包**：这一年的麦，田伯的最爱，放在最前；
   - **番茄炖土豆**：铺子里的家常，林婶的最爱；
   - **丰收汤**：沈先生私下找了一整章的那碗，这晚端到大家面前。
   其余的人各带自己的一碗。白婆婆带玉米南瓜粥，不算这三道，是她自己的那一碗。
5. 长桌一头留着外婆从前的位子。白婆婆只有认定食堂又开了，才会坐下去。她不致辞，尝一口，再挑别人的咸淡。
6. 沈先生不写长文，只留一句：「此味只应故乡有。」
7. 阿远吃完，天亮前从进村路离开，把铝锅留下。他还的是许多年前的一碗饭，不是留下来住。

## 9. 文案规范（v2 新增）

**语气指南**：暖、轻、慢；幽默克制，不玩烂梗；每个人有口癖（田伯「这孩子啊／记得不」+ 小时候趣事/林婶打算盘/小满直球/沈先生掉书袋/白婆婆唠叨收尾「我说完了」+ 刀子嘴点评/阿远话留半句）。

**硬规则**：

1. 单段对话 3~8 句，超了拆段；
2. 每条引导/教学先是一句「人物会说的话」，再夹带操作信息；
3. **回响检查**：新对话不得与已有细节矛盾；尽量回收前文埋的钩（小满的爆米花、白婆婆的头巾、沈先生的汤）；
4. 菜品 desc 2~3 句：第一句写味道，第二句写人；
5. **菜品命名**：遵守《组合表设计》§4.2（家常叫法、少西式词、不暗示没有的食材）；新菜进表前用「食堂小黑板会不会写」自检；
6. 不出现：死亡直白描写、说教、网络热梗、超出当前作物/食谱表的食材名。

**协作流程**：AI 按本规范起草 → 用户审定稿 → 修改留痕入《开发日志》。

**形态**：轻量对话层，触发式对话气泡 + 常驻跳过 + 存档已读不重播（`readTutorials`，`??=` 迁移；老存档缺省视为已读）。

- **排期**：M5-P0c。序章（§2.1）若同期做，只在新档播一次；教学气泡在序章之后。
- **触发写地点，不写页面名**（§2.2）：`farm` 现在由田地页打开，`canteen` 由厨房页打开，`shop` 由小铺页打开。地图接上后只改「谁打开这个地点」，台词不动。
- **角色分工**：田伯 = 农场（种、收）；林婶 = 杂货铺（卖给她）+ 指出「想吃的人在各自的地方」（现在先用订单页顶着）；白婆婆 = 食堂（做菜、图鉴、黑暗料理的「差一点」）。
- **教学即人设**：田伯不说「点击地块播种」，而说「记得不，你小时候就爱往田里钻。来，这袋小麦咱俩一起撒」。

- **明确不做**：独立任务列表、成就板、遮罩锁定逐步操作；P0c 也不做地图本身。

**验收**：新档从序章（或跳过）到第一笔卖出/交单，无系统弹窗式引导；跳过可用；已读不重复；老存档不重播。
