# 文档体系（真源与维护纪律）

> **本文是文档怎么分工的唯一真源。**  
> 改「某类事实写在哪 / 改完要同步谁」只改本文；其它文档文首只保留一句话角色 + 链到本文。  
> 目的：以后迭代时**不互相打架、不整段复述**。

- 创建：2026-09-29
- 适用：`docs/` 下全部 Markdown；改文档时 AI / 人都遵守本文

## 2. 反打架规则（硬）

1. **一事实一真源**：同一决策只在上表「真源范围」那一列的文档里写完整表述。  
2. **其它文档只链指针**：最多一句「详见 xxx §y」，禁止复制色板 / 提示词全文 / 批次状态表 / 底线勾选表。  
3. **状态只在一处勾**：里程碑/P0/P1 **完成与否** → 只改 `游戏开发方案.md` §6.x；体验底线勾选 → 只改 `体验内容开发方向.md` §4；故事线 §8 不得维护 ✅/待做。  
4. **数值真值在数据**：售价、时长、周期 → `data/*.json`（+ sim/balance）；设计文档写原则与字段，不抄易过期价目。  
5. **日志不当规格**：`开发日志.md` 可与现行口径不一致（史料）；冲突以真源文档为准。  
6. **先改文档再动手**：与方案总约束冲突的想法，先改真源文档并在日志留一行，再改代码/出图。  
7. **出图工具**：现行 = 即梦；禁止再把 ComfyUI 手册当操作真源。
