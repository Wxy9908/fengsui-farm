## 3. recipes.json 食谱表与组合解析规则

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 英文蛇形标识；发布后尽量不改（图标/存档/求购引用） |
| name | string | 中文菜名；**命名规范见《组合表设计》§4.2** |
| ingredients | object | `{作物id: 数量}`，多重集合（允许重复，如 `{wheat:2}`） |
| sellPrice | number | 菜品售价 |
| tier | number | 图鉴排序用层级 |
| desc | string | 两句制（味道 + 人/镇上的事）；不暗示表外食材 |
| favoriteOf | string? | 可选，某 NPC id |

烹饪时长由 `config.cookTimeByTier` 阶梯 + 食材数加成派生，不逐条填写（2026-07-26 试玩反馈定案）。

**组合解析规则（自由组合玩法的核心）**：

1. 玩家向厨房放入 1~3 个食材（槽位数见 config.maxComboSlots），顺序无关；
2. 系统将玩家选择的多重集合与每条食谱的 `ingredients` 做**完全匹配**（种类和数量都相等）；
3. 命中 → 产出对应菜品；若该食谱首次命中 → 触发"发现新食谱！"，点亮图鉴；
4. 未命中 → 产出兜底项 `dark_cuisine`（黑暗料理，售价极低，也进图鉴）。

伪代码：

```
resolveCombo(selected):                      # selected = {cropId: count}
  for recipe in recipes (跳过 dark_cuisine):
    if recipe.ingredients 与 selected 完全相等: return recipe
  return dark_cuisine
```

当前 15 种作物、最多 3 槽位的全部组合共 815 种。M3-② 扩表后共 40 条食谱（39 道 + 黑暗料理），发现率曲线：Lv1 52.6% → Lv3 32.7% → Lv5 17.6% → Lv8 4.8%（前期密集惊喜建立钩子，后期稀有维持追求；逐阶段测算详见 `docs/组合表设计.md` §2）。

## 4. upgrades.json 升级线表

每条记录代表某条升级线的一个等级（Lv1 为初始级，cost 0）。

| 字段 | 类型 | 说明 |
|------|------|------|
| line | string | `field` 田地 / `kitchen` 厨房 / `shop` 店铺 / `convenience` 便利 |
| level | number | 等级 |
| effect | object | `{type, value}`：`fieldSlots`=已解锁地块总数（19 坑位网格按中心向外解锁，见 §8.7）；`cookTimeMult`=烹饪时间倍率；`sellPriceMult`=售价倍率；便利线：`fertilize`=化肥催熟解锁、`harvestAll`=一键收获、`autoReplant`=自动重播、`offlineCapBonus`=离线上限 +N 小时、`comboSlotBonus`=组合槽 +N |
| cost | number | 升到本级的花费（金币） |

效果取值均为**该等级的绝对值/总倍率**，不累加，读表即用。

当前档位（2026-08-05 M3 验收回修定稿）：田地 Lv1~7 = 4/6/8/10/13/16/19 块（200/600/1800/5400/12000/24000 金）；厨房 Lv1~5 = 烹饪时间 0/-15%/-30%/-40%/-50%；店铺 Lv1~5 = 售价 +0/+15%/+30%/+45%/+60%；便利 Lv1~3 = 无 / 化肥催熟 3000（Lv9 门控）/ 一键收获 6000（Lv10 门控）。便利线定调「强大便利、价格高昂」（化肥=金币换时间，3000 起档；`fertilizeCost` 另计 200 金/次）。

便利线后续档位（自动重播、离线上限+Nh、组合槽+N）暂不开放购买，等后续内容（装饰线、活动等）丰富后再叠加；效果类型已在代码与数据表中预留。

## 7. 经济数值原则（2026-08-05 数值平衡验收通过）

- 作物时薪（利润/小时）随 tier 上升：T1≈80，T2≈90，T3≈120，T4≈150；同 tier 内时薪持平，短周期作物用"频繁操作"换收益。**T1 周期史**：2026-08-11 小麦/番茄/土豆 60/300/600→45/225/450（价格不动，时薪 60→80）；**2026-09-28 P0a** 番茄/土豆再缩 225/450→135/270，售价 11/20→9/16 守时薪 80（只动周期会抬时薪压过 T2，bot 永不改种——见开发日志教训）；小麦 45s 已够快未再动；
- 做菜溢价：菜品售价 ≈ 食材总价的 1.7~2.2 倍（2026-08-11 由 1.5~1.9 上调，见 §7.1 重新裁决），烹饪是主要增值手段；P0a 下调番茄/土豆售价后已同步压 T1 菜品售价，溢价仍落在带内；
- 黑暗料理售价 1 金币：失败有成本但不惩罚过重，图鉴进度保留探索动力。

### 7.1 数值平衡验收结论（2026-08-05，`npm run balance` 仿真）

方法：`sim/balance.ts` 静态体检 + 理想玩家 bot（完美食谱信息，每天 4 次上线 × 30 天，离线走 settleOffline 封顶）三策略对照（直卖流 / 做菜流 / 做菜+化肥）。bot 数据为收益理论上限，真实玩家低于此。

- **作物时薪全部达标**：15 种作物时薪对齐 T1≈80 / T2≈90 / T3≈120 / T4≈150（以 `crops.json` + balance 为准；下句旧「60」口径作废）；
- **菜品溢价全部达标（2026-08-11 重定档）**：40 道菜溢价 min 1.75 / 中位 1.90 / max 2.13，全部在新区间 1.7~2.2（原区间 1.5~1.9 随重新裁决作废）；
- ~~「直卖 vs 做菜」裁决：做菜收入为直卖流的 1.44 倍~~（**2026-08-11 查明作废**：该数字来自 8-05 回修前的未入库状态，回修（经验曲线拉陡 + `sellDishXpCap` 50→30）后从未重跑；git 起点复跑即为 0.87 倍——做菜流唯一结构性优势是卖菜经验带来的升级领先，cap 砍 40% 后丧失；且厨房「12 锅/天」硬顶使做菜收入不随等级 scaling，直卖流随田数 scaling，等级越高直卖越优）；
- **「直卖 vs 做菜」重新裁决（2026-08-11，组合拳修复）**：①`sellDishXpCap` 30→50（单变量对照：0.87→0.99，回修砍 cap 的初衷是治前期升级过快，cap 影响随菜价成长、前期占比小，副作用可控）；②全部菜品售价 ×1.16（溢价带 1.5~1.9 → 1.7~2.2，recipes.json v4→v5）。修复后 bot 对照：**做菜流/直卖流 = 1.09 倍**，做菜流 Lv10 D27 vs 直卖流 D>30，菜品占做菜流收入 65%——做菜在金币、经验、收集三线全面占优，支柱 2 修复成立。直卖定位不变：厨房产能之外的泄洪口。遗留观察项：做菜+化肥流收入略低于纯做菜流（化肥 ROI 在新溢价带下边际），M5 前后再评；厨房升级线「只减时长不加锅数」对收入零贡献是设计漏洞，并行锅位档留 M5 评审；
- **P0a 复跑（2026-09-28）**：番茄/土豆加速 + 售价/T1 菜价联动后，`npm run balance` 时薪阶梯完好、溢价 min 1.75 / 中位 1.90 / max 2.17、做菜流/直卖流 **1.09 倍**、做菜流 Lv10 D27——与 8-11 裁决同量级，**未破经济**；
- **等级曲线定稿**：理想玩家 Lv5≈D3、Lv8≈D9、Lv10≈D18~24，符合「前期即时正反馈、中后期 ×1.6~2.0 递增」原则；休闲玩家（1~2 次/天）约 2~3 个月满级，节奏合理；
- **等级曲线修订（2026-08-05 M3 验收试玩反馈）**：真人试玩「随便点两下就 3 级」——bot 节奏不等于真人感受，前期 xp 拉陡（Lv2 100→250、Lv3 270→600，逐级至 Lv10 17500），卖菜经验封顶 50→30。修订后 bot 节奏 Lv2≈D2、Lv3≈D3~6、Lv10≈D30；
- **烹饪时长修订（2026-08-05 同批）**：试玩「放进去就出菜」——`cookTimeByTier` {20/40/80/120}→{60/150/300/480}、食材加成 10→20（debugTimeScale 15 下实际等待 4/10/20/32 秒）；配合「发现食谱改出锅揭晓」，等待从纯进度条变为悬念（见《开发日志》2026-08-05）；
- **后期金币淤积确认（非数值问题）**：全部升级水槽约 6 万金，理想玩家 D18~24 即买穿，此后金币以每天数万速度淤积（30 天结余约 100~150 万）。这正是 §8.5 装饰外观线（零数值纯表达）要解决的问题——维持停车场原判，M3 后期/M4 评审装饰线，不靠通胀式抬价硬堵；
- **化肥定价定案（2026-08-05 M3 验收试玩反馈）**：试玩确认「肥料能换时间，不能便宜」——化肥从开局开放改为**便利线 Lv2 门控**（3000 金解锁，Lv9 资格），单价 50→200 金/次；一键收获上移至便利 Lv3（6000 金，Lv10 资格）。便利线定调「强大功能、价格高昂」，成为前期金币的远期出口。原 50 金观察项作废。

## 8. 农场等级系统与金币水槽（M3 计划，2026-07-26 定案）

### 8.1 定位：双轨进度

- **金币轴**：经营循环的流通货币，支付种子/升级/消耗品；
- **等级轴**：游玩深度的累积，门控内容解锁资格。
- 双轨咬合规则：**等级给资格，金币做支付**——升级线每一级、每种新作物种子、厨房槽位等，都要求「农场等级 ≥ N」才开放购买。防止"有钱即毕业"，也让每条循环行为都有双重收益。

### 8.2 levels.json 等级表（新增文件）

```json
{ "version": 1,
  "levels": [
    { "level": 1, "xp": 0,    "rewardGold": 0,   "unlocks": ["seed:wheat", "seed:tomato", "upg:field:2"] },
    { "level": 2, "xp": 100,  "rewardGold": 50,  "unlocks": ["seed:potato"] },
    { "level": 3, "xp": 260,  "rewardGold": 80,  "unlocks": ["upg:kitchen:2", "upg:shop:2"] }
  ]
}
```

- `xp`：升到该级所需**累计经验**；曲线原则——前期每次收获都接近升级（即时正反馈），中后期需求 ×1.6~2.0 递增（2026-08-05 数值平衡验收定稿，见 §7.1）；
- `rewardGold`：升级即领金币（升级仪式感 + 升级后立刻有钱买新解锁的东西，闭环）；
- `unlocks`：字符串门控清单，格式 `类型:id[:级]`，GameCore 查询种子店/升级面板时统一过 `isUnlocked(key)`。

等级曲线 Lv1~10 已随 M3-① 定稿，见 data/levels.json（上表仅为结构示例）。L6~L8 的 unlocks 已随 M3-② 填入新作物门控（Lv6 胡萝卜/白菜/香菇、Lv7 辣椒/茄子/花生、Lv8 葡萄/桃子）。

### 8.3 经验来源（每条核心循环行为都喂经验）

| 行为 | 经验（占位） | 设计意图 |
|------|------------|---------|
| 收获作物 | 5 × tier | 主轴，tier 越高越多 |
| 发现新食谱 | 50（**出锅时发放**，2026-08-05 定案：下锅不揭晓，等待变悬念，出锅=庆祝+点亮图鉴的集中高光） | 强化支柱 2（组合探索），一次性大额 |
| 卖出菜品 | 售价 / 10（单次封顶 **50**，与 config.sellDishXpCap 一致） | 让赚钱同时推进等级 |
| 重复烹饪已解锁食谱 | 2 × tier（出锅时，安慰性质；黑暗料理不加） | 重复劳动也有微薄进度 |
| 每日奖励 | 10 | 留存钩子顺手喂经验 |

### 8.4 升级时刻的表现要求（M3 美术 v1.1 同步）

升级弹窗 = 仪式感 + 预告：金光庆祝层（复用新食谱庆祝层骨架），展示「已解锁：草莓种子」+「下一级（Lv5）解锁：第 7 块地购买资格」。**预告比奖励更重要**——玩家随时知道"再玩一点能得到什么"。

### 8.5 金币水槽分层（解决后期金币无处消耗）

| 层 | 内容 | 性质 | 上线档位 |
|----|------|------|---------|
| 可重复消耗（无限水槽） | 化肥催熟：花金币立即完成/加速生长 | 金币换时间，永不封顶 | M3 |
| 高价便利（一次性） | 一键收获全部、自动重播上次作物、离线收益上限 +h、厨房组合槽 +1 | 定价为现有升级 5~10 倍（数千~上万金） | M3 |
| 装饰外观线 | 小屋翻新、栅栏样式、灯笼、地块皮肤 | 零数值，纯表达，契合外婆小屋/丰收祭叙事 | M3 后期评审 |
| 活动型水槽 | 丰收祭捐菜/捐金换限定装饰称号 | 包装成玩法而非按钮 | 随故事线规划（M5+）评审 |

数值原则：升级/便利线成本按 3~5 倍跳档，同时高 tier 作物与店铺加价让收入曲线同步爬坡，避免水槽变挫败。

### 8.6 存档结构增量

`save` 增加 `{ xp: number }`；等级为派生值（按 levels.json 查 xp 所在区间），不单独存。旧存档迁移：xp 缺省 0。

### 8.7 田地网格与解锁顺序（2026-08-04 原型定稿）

- 田地固定为 **3/4/5/4/3 共 19 个坑位**的菱形插缝网格（奇偶行错位半格），见 `docs/mockups/field.png`；
- 每个坑位有格坐标 `(dx, dy)`（相对网格中心）；**解锁顺序 = 按画面视觉距离 `dx² + (dy·stepX/stepY)²` 稳定排序**（同距离先上后下、先左后右），即从中间排正中心一圈圈向外扩散；
- `fieldSlots` 的值 = 已解锁坑位数，取排序结果的前 N 个；存档中未解锁坑位不占 `fields` 数组，渲染时显示为草地虚线坑 + 锁；
- 参考实现见 `sim/gen-mockups.js` 田地页网格段（`GRID_ROWS` / `byDist` 排序），落 Cocos 代码时参数换成实际的 stepX/stepY。

### 8.8 收集里程碑奖励（M4 留存钩子，2026-08-05 定案）

图鉴收集进度的阶段性金币奖励：达成即自动发放 + 庆祝弹层（复用升级庆祝层骨架），并预告下一个目标。只做触发与发放，不做独立里程碑列表页（保持最小）。

**milestones.json 结构**：

```json
{ "version": 1,
  "milestones": [
    { "id": "recipe_5", "type": "recipe", "threshold": 5, "reward": 200, "name": "食谱 x5" }
  ]
}
```

- `type`：`recipe` = 已发现食谱数（**不含黑暗料理**）；`crop` = 已点亮作物数（seenCrops）；
- `threshold`：达成门槛（合计发现数）；`reward`：一次性金币；`name`：弹层展示名（直接拼进「收集里程碑·{name}」）；
- id 唯一；同类型 threshold 递增（sim 有断言兜底）。

**门槛与奖励数值及理由**：

| 线 | 门槛 | 奖励（金） | 合计 |
|----|------|-----------|------|
| 食谱（39 道） | 5 / 10 / 15 / 20 / 25 / 30 / 35 / 39 | 200 / 400 / 700 / 1000 / 1500 / 2000 / 3000 / 5000 | 13800 |
| 作物（15 种） | 5 / 10 / 15 | 300 / 800 / 2000 | 3100 |

数值尺度参考（§7.1）：化肥 50 金/次、田地 Lv7 升级 8000 金、理想玩家 Lv10 约 D18~24。设计原则——递增但克制：单档最大奖 5000（= 全收集 39 道的仪式感封顶）不及田地 Lv7 一级升级费，全部领完 16900 金 ≈ 水槽总量 6 万的 28%，不构成数值通胀；食谱线密度高于作物线，因为发现食谱是主动探索行为（支柱 2），奖励权重向其倾斜。

**存档字段**：`claimedMilestones: string[]`（已领取里程碑 id）。旧存档迁移：构造时 `??= []`，随后 `checkMilestones()` 把已超门槛的全部一次性补发（事件入队，UI 逐个弹层、每层列出自己的奖励明细）。触发点：收获点亮作物、发现新食谱、出锅兜底各查一次；已领取 id 跳过，不重复发放。
